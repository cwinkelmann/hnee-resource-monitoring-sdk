# hrm SDK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** a dependency-free Python SDK (`import hrm`) for the carrot GPU booking server, plus an example notebook.
**Architecture:**
- `errors.py` holds the exception types.
- `models.py` holds frozen dataclasses parsed from JSON.
- `planning.py` holds pure day/window/capacity/GPU-choice logic.
- `client.py` holds the urllib HTTP client and the `book` orchestration.
- `__init__.py` exposes the module-level API backed by a default Client.

**Tech stack:** Python ≥ 3.9 stdlib; pytest; optional pandas.
**Spec:** `docs/superpowers/specs/2026-10-06-hrm-sdk-design.md`. Read it; it is the authority, including the server contract and exact `book()` semantics.

## Global Constraints
- **No runtime dependencies.** pandas is imported lazily, only in `.to_frame()`.
- **Python ≥ 3.9 syntax.** Use `from __future__ import annotations` in every module and no `match` statements. Don't use `X | Y` at runtime outside annotations.
- **Public repo:**
  - tests use only the anonymised fixtures in `tests/fixtures/` (alice/bob/carol/user04…, 192.0.2.10);
  - never add real user names, real IPs or credentials anywhere;
  - the default URL `http://10.188.1.1:8765` lives in exactly one constant, `hrm.client.DEFAULT_URL`.
- **HTTP:**
  - JSON with `Content-Type: application/json` on POST;
  - never send an `Origin` header;
  - 10 s timeout;
  - `User-Agent: hrm-sdk/<__version__>`.
- **Errors** map exactly as in the spec table. `.detail` is the server's `detail` if present, else its `error`.
- **Day semantics:** Europe/Berlin, via `zoneinfo.ZoneInfo("Europe/Berlin")`. Store and compare aware datetimes; send ISO with offset.
- **Commits** carry NO `Co-Authored-By` trailer or any AI-attribution line.
- **Local only:** never push and never touch GitHub. The only live-server contact allowed is in Task 5: the notebook run and the opt-in integration test.

## Review Focus
1. A `days` list containing **today**: the window starts at *now*, not 00:00. The server rejects starts older than 5 minutes. Tested in Task 2.
2. **DST change** inside a run (2026-10-25): the window end is local midnight, correct in UTC. Tested in Task 2.
3. **Non-consecutive days** produce several bookings on the **same GPU**. If a later one fails, the earlier ones are cancelled. Tested in Task 4.
4. **The server says 409 although the client's plan said the GPU fits** (a race): the SDK retries on the next candidate, at most twice. Tested in Task 4.
5. **The server is unreachable or returns 503 busy**: `ServerUnavailable` with a readable message, never a raw `URLError`. Tested in Task 3.

Subclasses: `InvalidRequest`, `Forbidden`, `NotFound`, `Conflict`, `RateLimited`, `ServerUnavailable`, `NoCapacity`, `UnknownUser`. `error_for_status(status, body: dict | None) -> HRMError` implements the spec's mapping (400/413/415 → `InvalidRequest`, 403, 404, 409, 429, 503 → `ServerUnavailable`; other 5xx → `ServerUnavailable`; others → `HRMError`).
- `models.py`: frozen dataclasses per the spec, each with a `from_json` classmethod:
  - `parse_time(s) -> aware datetime` (fromisoformat, `Z` → `+00:00`);

  - `BookingList.to_frame()` columns: `id, user, gpu, vram_gib, start, end, note, kind, cancelled`, with times in Europe/Berlin.
  - Both import pandas lazily and raise the spec's `ImportError` message without it.
  - `Booking.__str__` reads `"#12 GPU 4 · 48.0 GiB · alice · Tue 06 Oct 15:12 → Thu 08 Oct 00:00"` (Berlin time).

### Task 2: Pure planning (`planning.py`)
**Interfaces:**
- `TZ = ZoneInfo("Europe/Berlin")`, `MAX_DAYS = 14`;
- `parse_days(days) -> list[date]`: accepts `date` or `"YYYY-MM-DD"`; dedups and sorts; raises `ValueError` on a bad format;
- `day_runs(days: list[date]) -> list[list[date]]`: consecutive runs;
- `windows_for_days(days, now: datetime) -> list[tuple[datetime, datetime]]`:
  - one window per run, `[max(now, start of first day local), start of (last+1) day local)`, converted to UTC;
  - a past day (local date < today) raises `ValueError(f"{d} is in the past")`;
  - a run longer than 14 days raises `ValueError("a booking may last at most 14 days")`;
  - a window that would be empty (e.g. a day that is today but only if now ≥ end — can't happen) asserts;
- `window_from(start, end, now)`: naive means Berlin; requires `end > start`;
- `free_mib_at_worst(bookings: list[Booking], gpu: int, total_mib: int, start, end) -> int`: same rule as the server. The boundary instants are `start` plus each uncancelled booking on `gpu` whose start lies in `(start, end)`. At each instant, sum `vram_mib` of bookings active then; return `total_mib - max(sum)`.
- `choose_gpus(gpus: list[tuple[int, int]] (index, total_mib), bookings, windows, need_mib: int | None) -> list[int]`: GPUs that fit **every** window, in ascending index order. `need_mib=None` means the whole card, i.e. `free == total` in every window.
- `best_effort(gpus, bookings, windows) -> tuple[int, int]`: the GPU with the largest minimum free MiB, for the error message.

**Tests (TDD):**
- runs: `[6, 7]` gives one run, `[6, 8]` gives two, duplicates are removed, input order doesn't matter;
- today starts at now;
- a past day raises;
- 14 days are OK and 15 raise;
- DST: a run of 2026-10-24 to 2026-10-25 ends at 2026-10-26 00:00 CET = 2026-10-25T23:00Z;
- free-at-worst cases: none, partial overlap, back-to-back (an end equal to the window start doesn't count), cancelled bookings ignored, other GPUs ignored, a three-booking worst instant;
- `choose_gpus` with memory and whole-card cases;
- `best_effort`.

Use fixed `now` values with no wall clock.
**Commit:** `feat: day windows, capacity maths and GPU choice`

### Task 3: HTTP client (read API, errors, user resolution)
**Files:** `src/hrm/client.py`, `tests/fakeserver.py`, `tests/test_client.py`.
- `DEFAULT_URL = "http://10.188.1.1:8765"`.
- `class Client`:
  - `__init__(self, url=None, user=None, timeout=10.0)`: url comes from the argument, then `HRM_URL`, then `DEFAULT_URL`, with the trailing `/` stripped;
  - `_request(method, path, body=None) -> dict`: urllib only; JSON in and out;
    - an HTTPError becomes `error_for_status(code, parsed_body_or_None)`;
    - a URLError or timeout becomes `ServerUnavailable(None, f"cannot reach {url}: {reason}")`;
    - invalid JSON becomes `HRMError`;
  - `users()`, `usage()`, `bookings(days_ahead=14, days_back=7, include_cancelled=False)`: validate ranges (1..14, 1..30) client-side with `ValueError`;
  - `resolve_user(explicit=None) -> str`: the spec's order; it caches `users()` per client.
- `tests/fakeserver.py`: a stdlib `ThreadingHTTPServer` on 127.0.0.1:0 with a scripted router:
  - it serves the fixtures for GETs;
  - it records POST bodies and headers;
  - it can be told to answer a route with a given status and body;
  - it has a simple in-memory claims store implementing create (with a capacity check), cancel and quick, so `book` tests in Task 4 can run end to end.
  - Expose it as a pytest fixture `fake` (with a `.url`) in `conftest.py`.
- **Tests:**
  - each read endpoint parses;
  - `HRM_URL` env and arg precedence;
  - the User-Agent is sent, and no Origin is sent;
  - each error status maps to its exception, with `.detail`;
  - an unreachable server (a port with nothing listening) raises `ServerUnavailable`, and so does 503 busy;
  - user resolution: explicit wins; then `connect`; then the env var; then `getpass` (monkeypatched) if it's in the users list; otherwise `UnknownUser`, with the message naming the local login;
  - bad `days`/`back` ranges raise `ValueError` without an HTTP call.
- **Commit:** `feat: HTTP client, error mapping and user resolution`

### Task 4: Writes: `book`, `cancel`, `hold`, `release`, and the module API
**Files:** `client.py`, `src/hrm/__init__.py`, `tests/test_book.py`, `tests/test_module_api.py`.
- `Client.book(days=None, *, memory=None, gpu=None, start=None, end=None, note=None, user=None) -> BookingResult` exactly per the spec's `book()` semantics:
  - windows come from `planning`;
  - the candidates are `[gpu]` if given (still validated against the plan; if it doesn't fit, raise `NoCapacity`) else `choose_gpus`;
  - for each candidate up to 3 attempts: POST each window, sending `vram_gib` only if memory is not None, as `float(memory)`;
  - on a 409 at any window, roll back the bookings already created on this attempt and try the next candidate;
  - on any other error, roll back and re-raise;
  - once the candidates are exhausted, raise `Conflict` with the last detail.
- `BookingResult(gpu, bookings)` with `__str__` per the spec, plus `.ids`.
- `cancel(booking_or_id) -> Booking`, `hold(gpu, user=None) -> Booking`, `release(gpu) -> None`.
- `__init__.py`: `connect(user=None, url=None)` (re)creates the default client; the module-level `users/usage/bookings/book/cancel/hold/release` delegate to it; `__all__` covers every name plus the exceptions and models.
- **Tests** (fake server):
  - the user's example `book(days=[d1, d2], memory=48)` books ONE run on the lowest fitting GPU, with the correct UTC start/end;
  - non-consecutive days give 2 bookings on the same GPU;
  - a forced 409 on GPU 0 then success on GPU 1;
  - 3 forced 409s raise `Conflict`;
  - a second window failing with a 400 cancels the first, then raises `InvalidRequest`;
  - pinned `gpu` that doesn't fit raises `NoCapacity` without a POST;
  - no candidate raises `NoCapacity`, with the message naming the best GPU and its free GiB;
  - `memory=None` omits `vram_gib`;
  - `start`/`end` with naive Berlin times;
  - `cancel` by object and by id;
  - `hold`/`release` bodies;
  - the module-level API uses `connect()`'s user and url.
- **Commit:** `feat: booking with GPU auto-pick, retries and rollback; module API`
